Coding with AI, hands on

Practise asking for code clearly, understanding it before you use it, finding bugs, and testing what AI writes.

Asking for code clearly

Good prompts for code follow the same rules as other prompts, only more precisely. Say what you want, what language you are using, and what the result should do.

Anthropic suggests a test: show your prompt to a colleague with little background on the task. If they would be confused, Anthropic says Claude will be too, and a clear prompt helps any tool.

GitHub suggests being specific about your requirements and breaking complex tasks into smaller pieces. Anthropic also notes that if you only ask "can you suggest some changes", Claude will sometimes give suggestions instead of making them, so say which you want. Examples help: Anthropic recommends including 3–5 examples for best results.

Understand it before you use it

GitHub's guidance says to understand suggested code before you implement it. If you do not understand a suggestion, you can ask the tool to explain the code.

If you cannot explain a line, you do not yet own it. Ask "what does this line do?" and explain it back in your own words.

Finding bugs

MDN says errors can be roughly split into two types: syntax errors, where the code is written incorrectly, and logic errors, where it runs but does the wrong thing. MDN explains that when a value is not what you expect, you can use console.log() to print it and see what is happening. Browser developer tools also let you add breakpoints, which stop the code at a point so you can look at its state, and their console reports errors in your code.

An AI tool can help you read an error message. Still run the fix yourself and confirm that the bug is gone.

Tests and checks

GitHub's tutorial on reviewing AI-generated code says to run automated tests and static analysis tools first, and to make sure the code compiles and all tests pass. If your project has no tests yet, start with the simple checks below.

It warns you to watch out for hallucinated or suspicious packages—a library the AI names that may not exist—so verify packages yourself. It also says to watch for tests that were deleted or skipped instead of fixed, and to be skeptical of code that looks right but does not match your intent.
