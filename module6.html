Coding with AI: hands-on

Practice asking for code clearly, understanding it before you use it, finding bugs, and testing what AI writes.

Asking for code clearly

Good prompts for code follow the same rules as other prompts, but they need to be more precise. Say what you want, what language you are using, and what the result should do.

Try the quick test from Claude's prompting guide. Show your prompt to a classmate who is new to the task. If they find it confusing, the guide says Claude will too. A clear prompt helps any tool.

GitHub's guide recommends saying exactly what you need and breaking complex tasks into smaller steps. If you ask Claude to suggest changes, it may give you a list of ideas. If you want edits, ask for edits. Claude's guide also recommends giving three to five examples for best results.

Key idea: When asking for code, name the language and explain exactly what you want the code to do.

Understand it before you use it

GitHub's guide recommends asking about code you do not understand and testing suggested code before you use it.

A student asks an AI to write a JavaScript function that turns minutes into seconds. The AI suggests this code:

function toSeconds(minutes) {
  return minutes * 60;
}
console.log(toSeconds(2));
console.log(toSeconds(3));

The student asks, “What does line 2 do?” The AI explains that line 2 multiplies the number of minutes by 60 and gives back the result.

To check, the student works out that 2 minutes is 120 seconds and 3 minutes is 180 seconds. They run the code in the browser's JavaScript console and see 120 and 180, just as they expected.

Key idea: Make sure you can explain suggested code in your own words before using it.

Finding bugs

MDN says errors can be roughly split into two types: syntax errors, where the code is written incorrectly, and logic errors, where it runs but does the wrong thing. MDN explains that when a value is not what you expect, you can use console.log() to print it and see what is happening. Browser developer tools also let you add breakpoints, which stop the code at a point so you can look at its state, and their console reports errors in your code.

An AI tool can help you read an error message. Still run the fix yourself and confirm that the bug is gone.

Key idea: Use errors and unexpected values as clues, then run your fix to see if it works.

Tests and checks

GitHub's tutorial on reviewing AI-generated code says to run automated tests and use static analysis tools first, and to make sure the code compiles and all tests pass. If your project has no tests yet, start with the simple checks below.

GitHub also warns you to watch out for made-up or suspicious packages (libraries the AI names that may not exist), so verify each package yourself. It also says to watch for tests that were deleted or skipped instead of fixed, and to be skeptical of code that looks right but does not match your intent.

For a small website like this one, a test can be as simple as opening the page and trying each button.

Key idea: Run tests and review what changed before relying on AI-written code.
